# Правила работы с репозиторием

## Ветки

- `main` — всегда рабочее состояние. Прямые коммиты запрещены; изменения попадают только через Pull Request.
- Рабочие ветки создаются от актуального `main`:
  - `feature/<кратко>` — новая функциональность;
  - `fix/<кратко>` — исправления;
  - `content/<кратко>` — тексты и переводы;
  - `chore/<кратко>` — инфраструктура, зависимости, CI;
  - `claude/<кратко>` — ветки, созданные Claude.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `content:`, `chore:`, `docs:`, `refactor:`.

## Pull Requests

1. Один PR — одна задача. Открывается как Draft, пока работа не готова к проверке.
2. CI (lint, typecheck, проверка ключей переводов, форматирование, build) должен быть зелёным.
3. Слияние в `main` — только после явного одобрения владельца проекта, способом **Squash and merge**.
4. После слияния ветка удаляется.
5. Деплой выполняется только по отдельному решению.

## Безопасность

- Реальные ключи, токены и пароли никогда не коммитятся. Шаблон переменных — `.env.example`, реальные значения задаются только в настройках хостинга или в локальном `.env.local`.
- Этот репозиторий относится только к рекламному лендингу; основной корпоративный сайт Sparrow.Agency здесь не изменяется.

## Рекомендуемая защита `main` (GitHub → Settings → Branches)

- Require a pull request before merging (минимум 1 approval).
- Require status checks to pass: `CI / Lint, typecheck, messages, format, build`.
- Require linear history; запрет force-push и удаления ветки.
